## Flagged Assumption (specless-probe item, NOT resolved this phase)

REP-01's concurrency question — "if interrupted or run in parallel, what is guaranteed when two terminals race to close the same caja session?" — is explicitly OUT OF SCOPE per CONTEXT.md D-08 (single-terminal only, no concurrent-terminal/concurrent-cashier testing this phase). This plan does NOT test concurrent-close behavior. The existing `caja_sessions.version` optimistic-lock trigger (`bump_version_on_update`) provides some protection against a lost-update race, but its behavior under a genuine two-terminal simultaneous close is unverified by this phase. Revisit only if multi-terminal issues surface in real usage, per D-08's own scoping note.
