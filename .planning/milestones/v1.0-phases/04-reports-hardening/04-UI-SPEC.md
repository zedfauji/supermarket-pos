## Tab Removal — Structural Contract (D-01/D-02/D-04)

This is layout deletion, not new design — stated explicitly so the checker/executor don't invent new visual treatment:

- `reports.groups.menu` group (`src/pages/reports/index.tsx` lines ~76-85 as of research) is deleted in full — the `<div className="flex flex-col gap-1.5">...</div>` wrapper, its label `<span>`, and its one `TabsTrigger` all go together. No replacement UI.
- `reports.groups.staffTips` group keeps its wrapper `<div>` and pill container, loses the `tips` `TabsTrigger`, and its label copy changes from "Staff & Tips" to "Staff" (see Copywriting Contract). The `staff` `TabsTrigger` and its `TabsContent` are untouched.
- `TabsContent value="modifier-popularity"` and `TabsContent value="tips"` blocks are deleted along with their trigger — do not leave an orphaned `TabsContent` reachable by URL/state.
- `Tabs defaultValue="session"` is unaffected (default tab is not one of the removed ones).
- No new empty-state or placeholder is needed where the "Menu & Promos" group used to render — the group disappears, the remaining groups (Sales / Staff / Operations) simply occupy the space via the existing `flex flex-col gap-1.5` stacking; no gap/spacing adjustment required since each group is independently wrapped.

## UI Considerations

> State coverage for the one new UI surface (Margin column) and the deletion surface (tab removal).

Applicable state considerations resolved: 4 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Margin column, pre-cutover / no-cost-data rows | ✅ covered | Renders `"—"` with muted-foreground styling and a descriptive `aria-label`, never `$0.00` (see Copywriting Contract) |
| zero-one-many | Margin column, mixed known/unknown cost rows for the same product | ✅ covered | Margin is computed only from rows with a known `cost_price_snapshot`; unknown rows are excluded from both the cost and revenue-for-margin sum, per 04-RESEARCH.md Pitfall 2 — no partial-data visual indicator added (kept out of scope, YAGNI: no requirement calls for a per-row asterisk/footnote) |
| overflow | Margin column, existing `DataTable` horizontal layout with an added 6th column | 🧪 backstop | Table already renders 5 columns responsively (`ProductSalesPanel`'s existing `DataTable`); a 6th narrow numeric column is expected to fit the same way Revenue/%Total already do — no explicit responsive breakpoint test exists for this, flagged as backstop rather than assumed silently |
| long-text | Reports page tab groups after "Menu & Promos" removal and "Staff & Tips" → "Staff" rename | ✅ covered | Group label change is a shorter string in both locales (removes text, doesn't add), so no new wrap/overflow risk is introduced |
| populated | Margin column, normal case (all rows have `cost_price_snapshot`) | ✅ covered | Renders identically to the existing Revenue column via `MoneyDisplay size="sm"`, including existing negative-value red-text handling if a product is ever sold below cost |
