<objective>
Remove combos, recipes, ingredient costing, and modifier-inventory depletion rules entirely — 4 entities, 6 features, 5 widgets, and their DB schema — including a bespoke rewrite of the shared `deplete_for_order_item` function, which currently has combo/recipe depletion AND modifier-rule depletion branches interleaved with the open-unit depletion logic that MUST be kept.

Purpose: recipe-based ingredient costing, combo/meal-deal pricing, and modifier-driven inventory depletion are bar-menu concepts with no grocery equivalent (Phase Boundary). `open_units` (case-to-piece breakdown) is unrelated infrastructure reused by CHK-05 in Phase 2 and must survive this strip untouched.

**Highest-risk task in this plan (Pitfall 3):** `deplete_for_order_item` has 5 prior versions; v5 (`20260729000004_deplete_for_order_item_v5_open_units.sql`, read in full this session) interleaves recipe-loop depletion, modifier-inventory-rule depletion, and open-unit depletion in one function body. Reverting to an older version would silently lose the open-unit branch (v1-v3 predate it). This plan authors a fresh v6 that starts from v5's body and removes ONLY the recipe-loop and modifier-rule-loop branches.
Output: no combo/recipe/ingredient/modifier-rule code or DB object remains; `deplete_for_order_item` v6 correctly depletes plain-product and open-unit sales without the removed branches; `ModifierPopularityReport`/`get_modifier_popularity_report` are untouched (confirmed generic).
