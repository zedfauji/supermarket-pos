# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is not a greenfield design. Phase 1 left a fully-built design system in place (shadcn `components.json`, oklch token theme in `src/app/globals.css`, an established component library in `src/shared/ui/`). Phase 2 rebuilds `/pos` as a *composition* of that existing system — this contract documents what already exists (so the executor reuses it verbatim) and specifies only the handful of genuinely new elements (product search/grid, weight keypad, hold/resume banner, post-payment confirmation). Per `02-RESEARCH.md`, `PaymentForm` (D-14) and `CartItem`/`cartStore` mechanics carry over unchanged — no new visual design for those.

## Spacing Scale

Declared values (Tailwind's default 4px-based scale — already the project standard, confirmed in `tailwind.config.ts`/`globals.css`, no override present):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g. category-dot to label gap in `ProductCard`) |
| sm | 8px | Compact element spacing (`gap-2` between quantity buttons) |
| md | 16px | Default element spacing (`ProductCard`/`CartItem` internal padding `p-3`/`p-4`) |
| lg | 24px | Section padding (panel gutters between product grid and cart) |
| xl | 32px | Layout gaps (between `CheckoutPanel`'s major regions) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **touch targets follow `POSButton`'s `touchSize` convention, not the spacing scale** — `default` 44px, `large` 56px, `xl` 72px (established in Phase 32's touch-target sweep). Use `xl` (72px) for the "Process payment" CTA and the numeric keypad's digit buttons (matches `PINKeypad`'s existing 64px precedent, rounded up to the `large`/`xl` token); use `default`/`large` for secondary actions (Hold, Resume, Discard, category tabs).

## Typography

All roles reuse existing, already-in-production classes — no new type scale introduced. The table below is the budget for elements this phase writes fresh copy/markup for (weight keypad, hold/resume banner, category tabs, section headers). Pre-existing components this phase reuses unchanged (`AlertDialogTitle`, `DialogTitle`, `MoneyDisplay`) keep their own hardcoded classes and are called out separately below as inherited defaults — they are not additional entries in this phase's type scale.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 regular (`font-normal`) | 1.5 |
| Label | 14px (`text-sm`) | 400 regular (`font-normal`) | 1.5 |
| Heading | 24px (`text-2xl`, `font-heading`) | 600 semibold (`font-semibold`) | 1.2 |
| Display | 30px (`text-3xl`, `font-mono` for money) | 600 semibold (`font-semibold`) | 1.2 |

Distinct values declared: 4 sizes (14, 16, 24, 30), 2 weights (400, 600).

Usage mapping for this phase's new elements:
- **Body**: product names in the grid/cart (where newly laid out by this phase), weight-keypad helper text ("Weight × price = line total")
- **Label**: category tabs, `QuantityControl` readout, hold-banner status text
- **Heading**: "Products"/"Cart" section headers via `SectionHeader` — renders `text-2xl font-semibold` with `font-heading` (Playfair Display) applied automatically, matching this role's declared size/weight exactly, no manual class needed
- **Display**: weight-keypad running price label, and any other new Display-role text this phase writes outside `MoneyDisplay` itself

Component-default exceptions (pre-existing, reused unchanged per this phase's scope note — NOT part of the 4-size/2-weight budget above, do not override per-instance):
- `AlertDialogTitle` renders `text-lg font-semibold` (18px/600) — used for the discard-held-sale confirm dialog title (`src/shared/ui/alert-dialog.tsx:73`); weight matches the Heading budget (600), size (18px) is the component's own fixed default
- `DialogTitle` renders `text-base font-medium` (16px/500) — used for the weight-entry dialog title (`src/shared/ui/dialog.tsx:113`)
- `MoneyDisplay size="xl"` renders `text-3xl font-bold` (30px/700) — used for the cart total and "Sale complete — $X.XX" confirmation (`src/shared/ui/MoneyDisplay.tsx:28`); size matches the Display budget (30px) exactly, weight (700 bold) is the component's own fixed default and supersedes the 600 budget value for that reused component only

These three components predate Phase 2 and carry over unchanged (D-14 and the phase scope note) — their sizes/weights are fixed inherited behavior, not new declarations subject to this phase's type-scale limits.

## Color

Reuses the existing oklch token theme (`src/app/globals.css`) — dark mode is default per project convention, tokens auto-switch via `prefers-color-scheme`. No new colors introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | Page background behind product grid + cart panel |
| Secondary (30%) | `var(--card)` / `var(--secondary)` | `ProductCard` tiles, `CartItem` rows, hold-banner surface |
| Accent (10%) | `var(--primary)` | Reserved for: the "Process payment" CTA (`POSButton` default/primary variant), active category tab indicator, focus rings (`--ring`) |
| Destructive | `var(--destructive)` | Reserved for: error toast text ("Product not found"), the confirm button in the discard-held-sale dialog when styled destructive (see Copywriting Contract), out-of-stock validation errors |

Accent reserved for: **only** the primary payment CTA, the active category tab, and focus-visible rings — never for the quantity-stepper buttons, cart-line "remove" icon, or Hold/Resume buttons (those stay `outline`/`ghost` variant, matching `CartItem.tsx` and `QuantityControl.tsx`'s existing `variant="outline"`/`variant="ghost"` usage, so the accent color doesn't get diluted across every interactive element).

`--pos-accent`/`--pos-danger`/`--pos-warning`/`--pos-highlight` (jade/garnet/amber/emerald semantic tokens) are inherited from the pre-strip theme for domain status signals (table/session state, low-stock, best-seller emphasis) — **not used in Phase 2** (no pool tables; low-stock/near-expiry is Phase 3 scope). Do not repurpose them here.
