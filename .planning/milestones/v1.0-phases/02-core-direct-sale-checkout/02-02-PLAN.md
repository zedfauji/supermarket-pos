<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| USB HID scanner (acts as a keyboard) → `useBarcodeScanner` → cart | Untrusted input crosses here: any device emitting fast keystrokes ending in Enter is treated as a scan; the barcode string itself only ever reaches a parameterized `.eq('barcode', code)` query, never concatenated SQL. |
| Cashier browser → `record_audit` RPC (direct client call, `GRANT ... TO authenticated`) | Untrusted `p_before` payload (the raw scanned string) — stored as `jsonb`, never interpreted/executed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-02-07 | Tampering | Malformed/oversized barcode string reaching `record_audit`/product lookup | low | mitigate | Barcode is only ever used as a parameterized-query equality value and a `jsonb` field value — no string concatenation, no code execution surface. Prohibition P1: no code path in the failed-scan handler ever calls a product-insert/upsert — a scan can only ADD a cart line for an EXISTING product, never create one. |
| T-02-08 | Information Disclosure | Failed-scan audit log accumulating scan patterns attributable to a specific cashier (`auth.uid()` default) | low | accept | `audit_logs`' existing manager/admin-only RLS read policy already restricts visibility; D-11 explicitly requested this logging for catalog-backfill purposes — no new exposure beyond the audit log's existing access model. |
| T-02-09 | Denial of Service | Rapid repeated failed scans spamming `record_audit` inserts | low | accept | Bounded by the physical scan rate of a USB device and the existing 50ms keystroke-gap/Enter-terminated buffering in `useBarcodeScanner` — no unbounded loop is introduced; explicit rate-limiting is out of Alpha scope. |

No `npm`/`pip`/`cargo` packages are installed in this phase (RESEARCH.md's Package Legitimacy Audit: "Not applicable") — the mandatory supply-chain (`T-{phase}-SC`) row does not apply to this plan.
