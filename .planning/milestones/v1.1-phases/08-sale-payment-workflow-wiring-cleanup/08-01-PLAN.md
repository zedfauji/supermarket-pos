<objective>
Fix SALE-04: `useCheckoutSale.submit()` currently has zero offline guard — an attempted checkout while offline hangs on `fetch()` until Playwright's action timeout (documented failure mode in `e2e/11-offline.spec.ts`'s permanently-skipped pool-session test). Add a fail-fast `isOnline()` guard, thread the resulting `NETWORK_OFFLINE` error code through `PaymentForm.tsx` (which currently discards `AppError.code` when narrowing `runPayment()`'s return type), and show a dedicated blocking dialog distinct from both the ambient `OfflineBanner` and the generic toast-error path.

Purpose: A cashier mid-checkout on a flaky connection gets an immediate, clear "you're offline" interrupt instead of a frozen UI, and can retry once reconnected without the sale silently queuing (money-moving operations must never be blindly replayed, per REQUIREMENTS.md SALE-04 and the existing "Extending the offline mutation queue to payments" Out-of-Scope entry).
Output: `useCheckoutSale.submit()` fails fast when offline; `PaymentForm.tsx` shows a `ConfirmDialog`-based blocking dialog with Try Again/Cancel; 3 new Playwright tests prove the fast-fail, retry-success, and cancel-no-side-effects behaviors.
</objective>
