<objective>
Implement SALE-02: `create-staff/index.ts` currently has zero auth check — `const { name, role, pin } = await req.json()` accepts a request from any caller holding just the anon key and can create an admin account. This plan transplants the Bearer-auth + role-check pattern already proven in `process-payment/index.ts` (lines 92-119) into `create-staff`, adds Zod body validation and `locale`/`must_change_pin` support to the same insert, and builds the "Add Staff" UI that was previously entirely missing (StaffDashboard had no create-staff affordance at all — `e2e/22-staff-management.spec.ts`'s `SM2` self-skips today with `'UI not implemented'`).

Purpose: close the highest-severity gap in this phase (critical elevation-of-privilege — any anon-key holder can currently mint an admin account) and give admins/managers a working way to onboard staff without a database console.
Output: `create-staff/index.ts` rejects unauthorized/under-privileged callers before mutating anything; a new `src/features/create-staff/` feature (hook + dialog) is wired into `StaffDashboard.tsx`; `SM2` is rewritten to actually exercise the real UI (not skip) and is joined by a negative-auth test proving the role check works.

**Tracer-file-count note:** Task 1 below intentionally touches every FSD layer this capability spans (edge function → client contract → mutation hook → dialog UI → widget wiring → i18n → E2E) in one tracer task, per this project's tracer-first convention ("one file per layer the phase touches, wired end-to-end, carrying a real runnable verify"). Splitting the auth mechanism from its only consumer would leave an intermediate task with no independently-reachable, user-facing verification point — the planner judged the single coherent vertical slice preferable to an artificially-split, non-verifiable middle task.
</objective>
