<objective>
Fix `receive_shipment`'s cost/expiry overwrite bug: replace the `ON CONFLICT (product_id) DO UPDATE SET cost_price = EXCLUDED.cost_price, expiry_date = EXCLUDED.expiry_date` clause (the exact bug, `supabase/migrations/20260817000002_receive_shipment_atomicity.sql` lines 42-47) with a weighted-average-cost + earliest-expiry-wins merge, within the existing one-row-per-product `inventory` model — per CONTEXT.md D-01/D-02/D-03.

Purpose: restocking a product before its prior batch sells out currently silently destroys the prior batch's cost/expiry data (last-write-wins). This is the phase's highest-risk fix because it patches a live `SECURITY DEFINER` RPC already in production use by `supabase/functions/receive-shipment/index.ts`.

Output: `supabase/migrations/20260819000003_receive_shipment_weighted_avg_cost.sql`, pushed live to the self-hosted Supabase stack; a new integration test suite proving the merge formula end-to-end; one new regression test in the existing product-sales-report suite proving historical margin survives a restock.
