<objective>
Move every client-side Anthropic API call (brain.ts's agent chat tool loop, vision.ts's image/text extraction) behind one new Bearer-authenticated Supabase Edge Function (`agent-proxy`), remove the client-exposed `VITE_ANTHROPIC_API_KEY` and the `@anthropic-ai/sdk` dependency entirely, per SEC-01 and CONTEXT.md's D-01/D-02/D-03.

Purpose: today `new Anthropic({ apiKey, dangerouslyAllowBrowser: true })` ships a real, paid Anthropic API key inside the distributed Tauri binary — anyone who extracts the bundle gets a usable key with no spend limit. This plan closes that exposure without touching the tool-loop/RAG orchestration logic that already works (D-01: thin proxy, not a server-side agent rewrite).

Output: `supabase/functions/agent-proxy/index.ts` (new, Bearer-auth + pass-through proxy), `src/shared/lib/agent/anthropic-types.ts` (new, minimal local types), `callAgentProxy()` added to `edge-function-contracts.ts`, `brain.ts`/`vision.ts` fully swapped off the SDK, `@anthropic-ai/sdk` removed from `package.json`, a clean build-output grep.

**Tracer-first note:** the tracer's `<verify>` is a Vitest test that mocks only the edge-function/HTTP boundary (not a live Anthropic API call) — this is not a shortcut but the literal, mandated verification method for Success Criterion #2 ("a Vitest test mocking the edge-function boundary"), since this project's CLAUDE.md bans manual/live verification and no CI environment here can safely hold a real paid Anthropic key. It still proves a genuine multi-layer path: vision.ts's orchestration -> edge-function-contracts.ts's transport boundary -> parsed response -> business logic, not a single-function-in-isolation unit test.
</objective>
