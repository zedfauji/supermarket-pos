# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is quality-debt/mechanical, not new UI. Only two of its five items touch pixels: **QA-01** (loading/error states on `SupplierListPanel`, wiring only) and **QA-03** (entity-ID copy/link affordance on `AuditLogTable`, `EditHistoryTable`, `DeletionsPostCloseReport`, plus an ID-filter box on `/payments` and `/staff`). **QA-02** is Storybook stories only (no new runtime UI — out of this contract's scope). **QA-04** and **OPS-02** have no UI surface at all. This contract locks the two runtime-UI items to the project's existing visual language — it does not introduce a new pattern language.

| Property | Value |

The lucide `Copy` and `Check` icons (already an installed dependency, not yet used elsewhere in the codebase — verified via grep, zero prior `Copy`-icon or `navigator.clipboard` usage) are the only new icon imports.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged, reused from the existing system:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside the ID cell (`gap-1`) |
| sm | 8px | Copy-icon-button touch padding, row internal gaps (`gap-2`) |
| md | 16px | Default element spacing (`SupplierListPanel`'s existing `space-y-4`) |
| lg | 24px | Section padding (unchanged) |
| xl+ | 32/48/64px | Not touched by this phase |

Exceptions: the copy-icon button uses the project's existing 44px minimum touch target (`touchSize` convention already established for `Button`/`POSButton`) even though it renders visually small (`size="icon"`, `h-8 w-8` visual box) — the hit target, not the visible box, must meet 44px per the project's existing touch-target sweep. No new exception introduced beyond what already exists in the codebase.

## Typography

No new type scale introduced. Reuses exactly what's already established for tabular/ID content:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cell text) | 14px (`text-sm`) | 400 (regular) | 1.5 (Tailwind default) |
| Entity ID value | 12px (`text-xs`), `font-mono` | 400 (regular) | 1.5 |
| Error message (`role="alert"`) | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Empty-state title | unchanged (`EmptyState` primitive default) | — | — |

`font-mono text-xs` for ID values is not a new decision — it's the pattern already in production use for identifier-shaped values in `OpenUnitsTab.tsx` and `RefundsRegister.tsx`. QA-03 must match it exactly, not invent a new ID-display style.

## Color

No new palette. Reuses existing semantic tokens (CSS variables, `oklch()`, defined in `src/app/globals.css`):

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` | Table/panel surfaces (unchanged) |
| Secondary (30%) | `--muted` | Muted ID text color when not linked (`text-muted-foreground`) |
| Accent (10%) | `--primary` (via `Button variant="link"`) | **Reserved for exactly two elements added by this phase:** (1) the copy-icon button's hover/focus state, (2) the navigation-link styling on `payment`/`tab` and `staff` entity IDs (D-01/D-02). Not applied to any other element in this phase. |
| Destructive | `--destructive` | `SupplierListPanel`'s error message text (`text-destructive`), matching `InventoryPagePanel`'s exact existing pattern — no new destructive-action UI is added by this phase |

Accent reserved for: the copy-icon button (hover/focus only) and the `payment`/`tab`/`staff` entity-ID link text. Every other `entityType` (settings, caja_session, product, order_item, etc.) renders as plain `text-muted-foreground` mono text — no accent, no link, per D-02.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Copy-icon button (accessible name) | `t('common.copyId', { defaultValue: 'Copy ID' })` — icon-only button, so the aria-label IS the label; no visible text |
| Copy success feedback | Toast via `sonner.toast.success(t('common.idCopied', { defaultValue: 'ID copied to clipboard' }))` — matches `SupplierListPanel`'s existing `toast.success`/`toast.error` pattern, no new feedback mechanism |
| Entity-ID link (payment/tab) | The truncated ID itself is the link text (`Link` to `/payments?id={id}` or equivalent query param, per D-03); accessible name via `aria-label`: `t('wAdmin.viewPaymentAriaLabel', { id })` → "View payment {id8}" |
| Entity-ID link (staff) | Same pattern, `/staff?id={id}`; aria-label: `t('wAdmin.viewStaffAriaLabel', { id })` → "View staff member {id8}" |
| Suppliers loading state | No new copy — `TableRowSkeleton` renders `aria-label={t('common.loading.generic')}` (existing key, already translated in both locales) |
| Suppliers error state | Reuses `resultError.message` verbatim (already a translated `AppError.message` per `SALE-05`'s error-translation work) — no new hardcoded string; rendered as `<p role="alert" className="text-sm text-destructive">{resultError.message}</p>` exactly matching `InventoryPagePanel` |
| Destructive confirmation | Not applicable — QA-01/QA-03 add zero new destructive actions |
| ID-filter input (`/payments`, `/staff`) | Placeholder: `t('wPanels.filterByIdPlaceholder', { defaultValue: 'Filter by ID…' })` |

All new strings go through `react-i18next` with es-MX (byte-identical default) + en-US translations, in the `wAdmin` namespace for `AuditLogTable`/`EditHistoryTable`/Reports, `wPanels` for the `/payments` and `/staff` filter box, and `common` for the copy-button/toast copy (cross-cutting, reused across all three surfaces) — matching each file's existing namespace per `CLAUDE.md`'s i18n table. This satisfies the `i18next/no-literal-string` lint gate already enforced on these layers.

## UI Considerations

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | `SupplierListPanel` list | ✅ covered | While `useSuppliers().isLoading`, render `TableRowSkeleton` (3-4 rows) in place of the `<ul>`, per D-05 — exact reuse, no new skeleton component |
| error | `SupplierListPanel` list | ✅ covered | `resultError ? <p role="alert" className="text-sm text-destructive">{resultError.message}</p> : null`, per D-06 — byte-identical pattern to `InventoryPagePanel.tsx` line ~223 |
| empty | `SupplierListPanel` list | ✅ covered | Already handled pre-phase via existing `EmptyState` branch (`suppliers?.length === 0`) — QA-01 does not touch this branch |
| zero-one-many | Entity-ID cells (`AuditLogTable`, `EditHistoryTable`, `DeletionsPostCloseReport`) | ✅ covered | Copy-icon + optional link render per-row regardless of row count; DataTable's existing pagination/infinite-scroll (`hasNextPage`) is unaffected — QA-03 only adds a cell renderer, no new list-count logic |
| long-text / overflow | Full (non-truncated) entity ID vs. 8-char display | ✅ covered | Displayed value stays truncated to 8 chars (matching `EditHistoryTable`'s existing `.slice(0, 8)` convention); full untruncated ID goes in a `Tooltip` (`src/shared/ui/tooltip.tsx`, already installed) on hover/focus of the ID text, and the full ID (not the truncated display string) is what gets copied/linked — never the truncated substring |
| partial | Copy action when `navigator.clipboard` is unavailable/denied (e.g. non-secure context edge case) | 🧪 backstop | No confirmed fallback UI decided at spec time — executor should wrap the clipboard call in existing `Result<T>`-style error handling and fall through to `toast.error` on rejection; verify via a Playwright assertion that a rejected `navigator.clipboard.writeText` triggers the error toast, not a silent no-op |
| zero-one-many | ID-filter box on `/payments`/`/staff` — filter yields 0 results | ✅ covered | Reuses each page's existing empty-state pattern (no new "no results for this ID" copy needed) — filtering to zero rows is functionally identical to any other empty result set already handled by the existing list rendering |
