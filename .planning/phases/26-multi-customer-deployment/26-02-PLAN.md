<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `customers/customers.json` (human-edited) → shell/`gh`/`git` command construction | Every `name`/`repo` field is committed data, but it becomes untrusted input the moment it's interpolated into a shell command inside the workflow. |
| GitHub Environment `<customer>` ↔ `sync-customers` matrix job | Only the job iteration whose `environment:` resolves to that customer's Environment name can read that customer's `CUSTOMER_MIRROR_PAT`/`VITE_SUPABASE_ANON_KEY`. |
| self-hosted runner workspace ↔ next job's matrix iteration | The workspace and any materialized `customer` git remote / `.env.production` persist unless explicitly cleaned up between matrix iterations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-03 | Tampering | `customers.json` `name`/`repo` fields interpolated into `git remote add`/`gh` commands | high | mitigate | Task 3's allow-list regex (`^[a-z0-9-]+$`) validation step runs before any `git`/`gh` command in `sync-customers`, rejecting a malformed manifest entry with a specific error instead of shelling it out. |
| T-26-04 | Elevation of Privilege | A leaked `CUSTOMER_MIRROR_PAT` | high | mitigate | Fine-grained PAT scoped to `contents: write` on exactly one customer repo (never a classic/broad-scope PAT), stored only in that customer's own GitHub Environment secret — the long-form `environment: { name: ... }` binding (RESEARCH.md Pitfall 2) ensures a matrix iteration can only ever resolve its own customer's secret. |
| T-26-05 | Information Disclosure | Materialized `customer` git remote (embeds the PAT in its URL) and `.env.production` left on the persistent self-hosted runner workspace | high | mitigate | `git remote remove customer` + `.env.production` deletion in an `if: always()` step at the end of every matrix iteration, confirmed to fire even when an earlier step in that iteration failed. |
| T-26-06 | Tampering (of update integrity) | A missing or malformed `customers/<name>/tauri.override.json` silently shipping core's generic identity to a real customer | high | mitigate | D-08's fail-loud pre-build `Test-Path` gate, proven with a real negative-path dry run in Task 3 (job stops before `tauri-action` runs, non-zero exit, specific error naming the customer and missing path). |

</threat_model>
