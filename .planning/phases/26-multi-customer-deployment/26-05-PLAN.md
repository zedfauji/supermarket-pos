Prove D-17's "real update cycle through the new path" requirement end-to-end using a controlled test
installation on the self-hosted runner — not by asking a human to watch Taj's live till (this repo's
CLAUDE.md testing policy forbids that as a verification substitute; every check in this plan is a real,
automated install-and-update-cycle test). This is the two-hop migration Tauri's updater actually
requires: (1) one transition release, shipped through the STILL-UNTOUCHED old `publish-tauri` job,
whose only identity-relevant change is `plugins.updater.endpoints` now pointing at Taj's own mirrored
repo instead of core's — a real already-installed test client applies this update in place (same
signing key, so the signature check passes) and its baked config now points at Taj's own repo; (2) a
SECOND release published only through the new fan-out mechanism, proving that once migrated, the new
path is a complete, self-sufficient channel with no further help from the old path.

Purpose: `identifier` and `publisher` stay untouched this wave — only `updater.endpoints` moves — so
this transition is safe to ship through the exact same automatic-update mechanism every prior Taj
release already used. This is the last wave that touches `src-tauri/tauri.conf.json` before Plan
26-06 makes the truly irreversible change (stripping it to a generic placeholder).
Output: A proven, automated two-hop update-cycle test confirming a real client migrates from the old
channel to the new one with zero manual reinstall and zero dead window.
</objective>
