<objective>
Expand the tracer's `test_print`-only broker contract (Plan 19-01) to the remaining three print commands
— `print_receipt`, `print_raw_text` (which did not exist as a Tauri command before this plan, despite
`CajaDashboard.tsx` already calling it), and `open_cash_drawer` — so all four commands `pos-printer.ts`
exposes route through the same `submit_to_broker` contract, on the same `Result<{ jobId: string }>`
shape Plan 19-01 established.

Purpose: D-09 requires one submission contract across every existing caller with zero public API
signature changes. This plan is the Rust/frontend-only half of that migration (no `broker/` crate
changes — the ledger/HTTP/delivery layer built in Plan 19-01 is already generic across job types via the
`origin` field, so only the Tauri command layer and `pos-printer.ts` need new call sites).
Output: `print_receipt`, `print_raw_text`, `open_cash_drawer` all return broker job IDs; the dangerous
pre-existing "write fallback bytes then report success" behavior is removed from the Windows path for
every migrated command.
</objective>
