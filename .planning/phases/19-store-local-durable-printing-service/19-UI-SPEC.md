# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is a printing-boundary hardening + audit-surface phase, not a new visual
system. Per CONTEXT.md D-09, all 6 existing print callers (checkout, `ReprintButton`, `PaymentForm`,
`PaymentPane`, `payment` queries, help content) keep their exact current UI — `pos-printer.ts`'s public
API and call sites are unchanged; only its internals swap to broker submission. The only genuinely new
UI surfaces this phase adds are: (1) a shared, non-blocking print-job status badge + "Did this print?"
confirm affordance (D-05/D-06/D-07/D-08), reused across every job type, and (2) a new "Print Jobs" tab
on the existing `/audit` page (D-13), reading from a new broker-backed `entities/print-job` data source
(RESEARCH.md Pitfall 5 — different data source than `entities/audit-log`, same reusable UI patterns).
Every visual choice below reuses proven, already-shipped components (`StatusBadge`, `ConfirmDialog`,
`DataTable`, `AuditLogDetailSheet`'s Sheet pattern, `sonner` toasts, `tabs.tsx`) rather than inventing
new ones.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | `/audit` page background (via `PageContainer`, unchanged) |
| Secondary (30%) | `var(--card)` / bordered panel (`border` + transparent bg) | Print Jobs table wrapper (`DataTable`, matches `AuditLogTable`'s existing styling), detail Sheet surface (`var(--popover)`) |
| Accent (10%) | `var(--primary)` | Reserved for: the active `TabsTrigger` state ("Audit Log" / "Print Jobs" — existing `tabs.tsx` pattern, unchanged), focus-visible rings on the confirm dialog's buttons (existing pattern) |
| Destructive | `var(--destructive)` | Reserved for: `print_failed` status badge, the terminal-failure toast's implied severity (`toast.error`, existing red/destructive sonner styling) |

**New status-badge tiers (not full-app accent/destructive reservations — scoped to this phase's job
states only):**

| Print job status | Color token | Rationale |
|---|---|---|
| `accepted` / `submitted_to_os` (in progress) | `var(--secondary)` / `var(--muted-foreground)` | Neutral, not-yet-settled — same treatment as existing `closed`/`po_draft` tiers |
| `completed` (OS-reported) | `var(--pos-accent)` (jade) | Matches this codebase's existing "positive/available" semantic (`pos-accent`'s own code comment: "table available") |
| `failed` | `var(--pos-danger)` | Matches existing "danger" semantic (`pos-danger`'s own code comment: "table occupied / danger") |
| `unknown` (ambiguous handoff, D-06) | `var(--pos-warning)` (amber) | Matches this codebase's existing "needs-attention" semantic, same amber already used for low-stock/near-expiry alerts (`pos-warning`'s own code comment) — **never** `pos-danger`/destructive, since `unknown` is explicitly not a proven failure (PRN-07) |
| `cancelled` | `var(--secondary)` / `var(--muted-foreground)` | Neutral, same treatment as `voided`/`closed` |

Accent is never applied to a status badge's resting state, table row backgrounds, or the "unknown"
badge (which must read as amber/warning, not accent-blue/primary) — reserved strictly for the two
items listed above.

## Interaction Contract

### Shared print-job status badge + confirm component (D-05/D-06/D-07/D-08)

- **One component** (`PrintJobStatusBadge`, `src/shared/ui/`), used identically wherever a print job
  can be triggered: `ReprintButton.tsx` (D-05's named extension point), `PaymentForm`, `PaymentPane`,
  caja summary print, test-print (Settings/Hardware), cash-drawer trigger. No feature-specific
  variant — the same visual/behavioral contract everywhere (D-07).
- Renders **inline, next to the triggering control** (e.g. beside `ReprintButton`'s existing
  `POSButton`), not as a modal or a separate page section — it augments the existing button, it does
  not replace it.
- **Non-blocking (D-08):** for every status except `unknown`, the badge is a small `StatusBadge`-style
  chip with no required interaction — the cashier can keep working regardless of print status. For
  `unknown`, the badge itself is clickable/tappable and opens the confirm dialog on demand; it is
  **dismissible** (an explicit "×" or tap-to-dismiss on the badge) without forcing resolution first —
  dismissing hides the badge but does not change the job's `unknown` status in the audit ledger.
- **Confirm dialog (D-06):** reuses `ConfirmDialog` verbatim — `title` = "Did this print?",
  `description` = the copy above, `confirmLabel` = "Yes, it printed" (`onConfirm`: dismiss the badge,
  no reprint, no further action), `cancelLabel` = "No, print again" (`onCancel`: trigger an explicit
  reprint of the same job's original content through the existing `printReceipt`/equivalent function,
  then dismiss the badge). `variant="default"` (neither answer is destructive). **The broker/UI must
  never auto-resubmit an `unknown` job** — the only path to a reprint is this explicit "No" click.
- Icons (lucide, `h-3 w-3` matching `RoutingBadge`'s existing icon-in-badge sizing): `Clock` for
  `accepted`/`submitted_to_os`, `CheckCircle2` for `completed`, `XCircle` for `failed`, `AlertTriangle`
  for `unknown`, `Ban` for `cancelled`.

### Error propagation to UI-originated callers (D-11, D-12, PRN-02/PRN-04)

- Every one of the 6 migrated callers must render a `sonner` `toast.error(...)` on a terminal failure
  — no silent discard. Use the three error-toast copy keys above, chosen by failure class:
  broker-unreachable (connect-timeout, D-12's ~1-2s client-side timeout expiring) vs. rejected
  (structured 4xx from the broker: auth/payload/persistence) vs. exhausted-retries (terminal after
  D-10's per-failure-class retry policy gives up).
- A **successful** durable acceptance (the broker returns a job ID) shows no toast by default — this
  matches the existing `printReceipt` UX (the sale/action itself already succeeded; print is
  best-effort from the cashier's perspective) and avoids toast fatigue on the fast-checkout path. The
  new status badge, not a toast, is how the cashier learns about eventual outcome.
- Background/non-UI callers (e.g. the `payment` query module) must still explicitly handle and log the
  `Result` (per D-11) even though they have no toast surface of their own — this is a code-level
  contract (see RESEARCH.md), not a new visual element.

### Print Jobs tab (D-13, RESEARCH.md Pitfall 5)

- **Placement:** a new `TabsTrigger`/`TabsContent` pair added to the existing `/audit` page
  (`src/pages/audit/index.tsx`), which currently renders `AuditLogTable` directly with no `Tabs`
  wrapper. Wrap the page in `Tabs defaultValue="auditLog"` (mirrors `ReportsPage`'s exact existing
  pattern) with two tabs: "Audit Log" (existing `AuditLogTable`, unchanged) and "Print Jobs" (new
  `PrintJobsTable` widget).
- **RBAC (D-16):** no new gate — the entire `/audit` page (both tabs) stays behind the existing
  `view_audit_log`-gated route; the Print Jobs tab is not separately permissioned.
- **Data source (Pitfall 5 — do not reuse `useAuditLogs`):** new `entities/print-job` query hook
  reading through a new Tauri command to the broker's `/audit` + `/jobs/{id}` HTTP endpoints — a
  different data source from Supabase-backed `entities/audit-log`, but composed with the **same UI
  components** as `AuditLogTable` (`DataTable`, a Sheet-based detail view).

## Print Jobs Tab Contract (`PrintJobsTable`)

- **Component:** `DataTable` (existing, TanStack-Table-backed) — same choice `AuditLogTable` already
  made, for the same reason (multiple sortable/filterable columns: origin, printer, status, time).
- **Columns:** Job ID (`EntityIdCell`-style short/copyable cell, matches `AuditLogTable`'s
  `entityId` column treatment), Origin (checkout / reprint / caja-summary / test-print / cash-drawer —
  plain text, matches `AuditLogTable`'s `entityType` column), Printer name, Status (`PrintJobStatusBadge`,
  new — see Interaction Contract), Attempts (plain number), Created at (`toLocaleString()`, matches
  `formatAuditDate` verbatim), row-click opens the detail Sheet (no separate "view" button/column
  needed on desktop rows since the whole row is clickable — matches `AuditLogTable`'s existing
  `onRowClick` pattern; **but** the Job ID cell still needs an `sr-only` accessible trigger analogous
  to `AuditLogTable`'s hidden "View diff" button, for keyboard/screen-reader parity: `aria-label`
  `"View print job {jobId} from {createdAt}"`).
- **Detail Sheet:** mirrors `AuditLogDetailSheet`'s existing right-side `Sheet` shape, but shows an
  **event timeline** (per-attempt/status-transition rows: timestamp, event type, normalized error if
  any, Windows job ID if assigned) instead of a before/after diff — the broker's `events` table is
  naturally a timeline, not a two-state diff, so `JsonDiffViewer` is not reused here; a simple ordered
  list (timestamp + event label + optional error text, `text-sm`, matches existing Sheet body
  typography) is sufficient and does not require a new shadcn component.
- **Filters:** origin, printer name, status, and date range — same staged-filter-then-Apply UX as
  `AuditLogFilterBar` (reuse that component's pattern/shape for a new `PrintJobFilterBar`, not a
  divergent filter UI).
- **Loading state:** `TableRowSkeleton` (existing, already used by `AuditLogTable`/`SupplierListPanel`).
- **Empty state:** `EmptyState` (existing component), copy per the Copywriting Contract above,
  distinguishing "no jobs at all" vs. "no jobs match these filters" exactly as `AuditLogTable` already
  does for its own three empty-state branches (`status === 'error'`, filtered-empty, unfiltered-empty).
- **Retention note surfaced in UI:** since payload bytes are purged after the retention window (D-14,
  pinned to 14 days per RESEARCH.md Assumption A1) while metadata is retained indefinitely, a job older
  than the retention window shows its metadata normally but the detail Sheet's payload preview (if any
  is ever added) must degrade to "Payload no longer available" rather than a blank/broken state — no
  payload preview is required by this phase's scope, but the detail Sheet must not error if
  `payload` is absent for an old job.
