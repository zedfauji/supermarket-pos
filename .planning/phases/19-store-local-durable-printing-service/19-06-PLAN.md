<objective>
Build the frontend read path for print-job status and history — a new `entities/print-job` query layer
backed by two new Tauri commands that call the broker's HTTP API (never Supabase), a shared
`PrintJobStatusBadge` implementing the phase's 6-way status vocabulary, and the "Did this print?"
confirm/reprint affordance wired into `ReprintButton.tsx` (the extension point D-05 names).

Purpose: PRN-05 requires audit queries filterable by time/origin/printer/job ID, which the spike's
minimal `GET /audit` (counts-only) and `GET /jobs/{id}` (single-job) endpoints do not yet support — this
plan closes that API gap first, then builds the frontend on top of it. PRN-07 requires cancellation as
its own distinct state, which the spike folded into `failed` — this plan splits it out.
Output: `broker/src/http.rs` gets a new `GET /jobs` list endpoint; `entities/print-job/` exists;
`PrintJobStatusBadge` and the unknown-status confirm flow are live on `ReprintButton`.
</objective>
