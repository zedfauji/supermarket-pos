<objective>
Turn Plan 19-01's foreground `broker/` binary into a genuine SCM-registered Windows Service, bundled and
auto-installed by the Tauri NSIS installer, running under a dedicated least-privilege account with a
per-store generated secret and a LAN-scoped firewall rule — closing the two production gaps Spike 001
explicitly left open (real SCM registration instead of `nssm`, and the untested cross-machine LAN
binding's firewall prerequisite).

Purpose: D-01 requires the real `windows-service` crate (no `nssm` in production); D-03 requires the
broker to ship inside the same installer as the POS app with one elevated post-install action; D-04
requires a per-store secret generated at install time, never a hardcoded/shared one.
Output: `broker.exe install`/`uninstall` CLI subcommands, a `windows/hooks.nsh` NSIS post-install hook,
updated `tauri.conf.json` bundling `broker.exe` as an installer resource, and an elevated PowerShell
verification script for the parts of this plan that require real Windows Service infrastructure this
agent's sandboxed shell cannot exercise directly.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Windows SCM -> broker.exe service process | the service account's privilege level bounds the blast radius of a compromised broker process |
| NSIS installer (elevated) -> service registration + firewall rule | a one-time elevated action; any bug here runs with full install-time privilege |
| LAN/VPN network -> firewall-scoped port 8973 | the boundary Pitfall 1 identified as untested by the spike |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-06 | Elevation of Privilege | Windows Service account | high | mitigate | NT SERVICE\PrintBrokerService dedicated virtual account, never LocalSystem/LocalService/NetworkService — a compromised broker process cannot leverage LocalSystem's full-machine privilege |
| T-19-07 | Tampering | Windows Firewall rule scope | high | mitigate | Rule scoped to the `private` network profile (LocalSubnet-equivalent for this store's trusted LAN/VPN), never `public`/`any` — closes Pitfall 1 without over-exposing the port |
| T-19-08 | Spoofing | per-store secret generation entropy | medium | mitigate | Two concatenated UUIDv4 values (already-audited uuid crate, OS CSPRNG-backed) — ~256 bits of entropy, no hand-rolled RNG, satisfies ASVS V6 without a new dependency |
| T-19-09 | Denial of Service | crashed broker.exe with no restart policy | medium | mitigate | `sc.exe failure` recovery policy applied at install time (three restart actions at 5s spacing) closes the "durable-but-stalled-until-a-human-notices" gap RESEARCH.md's Anti-Patterns flags |
</threat_model>
