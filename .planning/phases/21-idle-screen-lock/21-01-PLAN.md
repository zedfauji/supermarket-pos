<objective>
Build the idle screen-lock mechanism end-to-end: after a configurable per-terminal inactivity
timeout (default 60s, D-03), every screen for every role — including admin, including mid-transaction
(D-01) — locks behind a non-dismissable PIN overlay. Any valid staff member's PIN unlocks it without
changing the active session's identity (D-03/D-04), and both the lock and unlock events are fully
attributed in `audit_logs` (D-05). The per-terminal timeout itself is stored in a new
`terminal_lock_settings` table keyed by `TERMINAL_ID` (D-02) and is admin-only editable.

This plan is the phase's tracer: it wires idle-detect -> overlay -> cross-staff PIN-unlock ->
audit_logs for one full lock/unlock cycle, proven end-to-end via a real Playwright test, then expands
into the admin-facing Settings UI. Plan 21-02 hardens the remaining D-01 edge (no exemption for an
in-progress transaction) and closes a global-listener bypass risk (Pitfall 3) once this plan's core
mechanism exists.

Purpose: a physically unattended, already-authenticated till must never sit open — LCK-01..04 are this
phase's full formal scope.
Output: `terminal_lock_settings` table (live on the remote project), `AuditActionSchema` extended with
`screen.lock`/`screen.unlock`, the `features/idle-screen-lock/` feature (idle-detection hook, overlay,
provider), a `LockSettingsTab` in Settings, and Playwright/Vitest coverage proving LCK-01..04.
</objective>

| Boundary | Description |
|----------|-------------|
| Staff (physical, unattended terminal) -> IdleLockOverlay | Untrusted physical access to an unattended, already-authenticated terminal — anyone standing at it can attempt PINs |
| Client (React) -> Supabase RLS (terminal_lock_settings) | Client-submitted timeout writes cross into RLS-enforced Postgres |
| Client (React) -> record_audit RPC | Client-submitted audit payloads (p_before/p_after JSON) cross into a SECURITY DEFINER function |
