# Phase 21 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, no re-init needed) |
| Preset | `radix-nova` style (existing `components.json`) |
| Component library | radix (`@radix-ui/react-alert-dialog`) |
| Icon library | lucide |
| Font | `Geist Variable` (sans/body), `Playfair Display` (`font-heading`, used for dialog/section titles) |

**Zero new components for this phase.** Every UI surface reuses already-shipped `shared/ui` primitives
verbatim: `AlertDialog`/`AlertDialogContent`/`AlertDialogHeader`/`AlertDialogTitle`/
`AlertDialogDescription`/`AlertDialogFooter` (`shared/ui/alert-dialog.tsx`), `PINKeypad`
(`shared/ui/PINKeypad.tsx`), `Input`, `Label`, `POSButton`, `ProtectedAction`. No `npx shadcn add`
call is needed. The two new pieces of UI in this phase (`IdleLockOverlay`, `LockSettingsTab`) are
**compositions** of these existing primitives, modeled directly on `ManagerPinDialog.tsx` (overlay)
and `NearExpirySettingsTab.tsx` (settings tab) — see RESEARCH.md Recommended Project Structure.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from the project-wide scale already in use
across `ManagerPinDialog`/`NearExpirySettingsTab`; this phase introduces no new spacing values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (backspace icon padding) |
| sm | 8px | Keypad grid gaps (`grid gap-2`), compact stacks |
| md | 16px | Default vertical stack spacing (`space-y-4`), dialog content gap |
| lg | 24px | Dialog content padding (`AlertDialogContent p-6`) |
| xl | 32px | Not used in this phase's surfaces |
| 2xl | 48px | Not used in this phase's surfaces |
| 3xl | 64px | Not used in this phase's surfaces |

Exceptions: PINKeypad's numeric keys are 64px × 64px (`h-16 w-16` equivalent) — a pre-existing
touch-target exception from `PINKeypad.tsx`, not new to this phase. `AlertDialogAction`/`Cancel`
touch height is 56px (`min-h-[56px]`) — also pre-existing. The unlock overlay has **no**
`AlertDialogCancel`/`AlertDialogAction` footer at all (see Copywriting Contract — non-dismissable),
so this exception only actually surfaces via the PINKeypad's own keys.

## Color

This project uses semantic OKLCH CSS-variable tokens (`src/app/globals.css` `@theme`), not
hardcoded hex — declaring token names in place of hex per that convention:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--popover` (`bg-popover/90` + `backdrop-blur-md`) | Overlay/dialog surface — both `IdleLockOverlay` and the underlying page (`--background`) sit behind it |
| Secondary (30%) | `--muted` / `--secondary` | Description/hint text (`AlertDialogDescription`, settings hint `text-xs text-muted-foreground`), unfilled PIN dots, disabled keypad key backgrounds |
| Accent (10%) | `--primary` | **Reserved for:** the `LockSettingsTab` "Save Timeout" `POSButton` only. Not used anywhere else in this phase — `PINKeypad` number keys stay `variant="outline"` (no accent-colored keys), matching `ManagerPinDialog` precedent exactly. |
| Destructive | `--destructive` | **Reserved for:** the incorrect-PIN error state only — `PINKeypad`'s red-bordered PIN display (`border-destructive`) and error text (`text-destructive`), reused verbatim from `ManagerPinDialog`'s existing error handling. No other destructive actions exist in this phase. |

Accent reserved for: `LockSettingsTab`'s Save Timeout button — the single primary CTA this phase
introduces. Everything else (keypad keys, overlay chrome) is neutral by design, matching the
zero-new-visual-surface intent of reusing `ManagerPinDialog`.

| Empty state heading | Not applicable — this phase has no list/collection UI (no `list-collection` element kind present) |
| Empty state body | Not applicable — see above |

## UI Considerations

Applicable state considerations resolved: 4 covered, 2 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | IdleLockOverlay (form/interactive-control — PIN entry) | ✅ covered | Reuses `PINKeypad`'s existing `isLoading` prop verbatim (spinner replaces PIN dots, all keys disabled) while `useStaffList()` is in flight — identical to `ManagerPinDialog`'s current behavior (`isIdleOrLoading`). |
| error | IdleLockOverlay (form) | ✅ covered | Incorrect-PIN error render is the `idleLock.incorrectPin` copy row above, styled via `PINKeypad`'s existing `error` prop (red border + `role="alert"` text) — no new error UI. |
| empty | IdleLockOverlay (form) | ✅ dismissed | Not applicable: the overlay is a PIN keypad, not a rendered list — there is no "zero staff" collection UI to render empty. If `useStaffList()` ever returns zero staff, every entered PIN simply fails to match (falls into the `error` row above); no separate empty-state UI is needed. |
| loading | LockSettingsTab (form) | 🧪 backstop | Settings-fetch loading state (`useTerminalLockSettings` in flight) is not concretely specified beyond "matches `NearExpirySettingsTab`'s pattern" (which itself has no explicit skeleton — the input just renders the DB default of 60 until the query resolves). Verify at implementation time that this doesn't flash an incorrect value; if a skeleton/disabled-input state is added, it must match `NearExpirySettingsTab`'s equivalent (currently none). |
| error | LockSettingsTab (form) | ✅ covered | Save failure reuses `NearExpirySettingsTab`'s exact `toast.error(result.error.message)` pattern — see Copywriting Contract. |
| overflow / long-text | IdleLockOverlay, LockSettingsTab | ✅ dismissed | PIN entry is fixed-length numeric (4–6 digits per `maxLength`), no free text; the timeout input is a 3-digit-max number field (`15`–`600`) — neither surface can overflow or contain long text. |
