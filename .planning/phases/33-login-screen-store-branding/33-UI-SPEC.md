# Phase 33 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** (1) `LoginPage`'s desktop-only left brand panel (`hidden lg:flex` aside), reshaped
to show a hero-size store logo + real store name above the existing date/clock/tagline block (D-04/D-06); its
unconfigured fallback (generic name + small icon, D-03); (2) a new store-logo upload control added to
`GeneralSettingsTab`, alongside the renamed `storeName` field (D-11); (3) every new UI string this introduces.
All 12 CONTEXT.md decisions (D-01..D-12) are treated as locked and are not re-asked. This session was
non-interactive — no user questions were needed; every open design question below is resolved with a default
derived from the existing "Counter" token system (`src/app/globals.css`, `DESIGN-TOKENS.md`) and Phase 31's
already-approved Photo-tab pattern (`31-UI-SPEC.md`), with rationale recorded inline.

**Explicitly NOT touched (per D-05 and CONTEXT.md canonical refs' line range):** the mobile header row
(`mb-8 flex items-center gap-3 lg:hidden`, `LoginPage` lines ~73-82) — it keeps its exact current markup,
sizing, and the hardcoded generic `t('login.brand')` string. It is **not** wired to `storeName`/the new logo;
enlarging or rebranding it is explicitly rejected by D-05.

## Layout & Interaction Contract

### 1. Login hero header block (`LoginPage`, desktop aside only — D-04/D-06)

Replaces the current `relative flex items-center gap-3` block (lines ~42-56) with a **branching** render:
configured vs. unconfigured. Both branches sit in the same position — the top of the aside, above the
existing `space-y-6` date/clock/tagline block, which is otherwise **completely unchanged** (D-06: "added...
not a replacement").

**Configured** (`general.storeName` non-empty **and** `general.storeLogoPath` set and its signed URL resolves):

```
<div className="relative flex flex-col items-start gap-4">
  {/* Hero logo tile */}
  <div className="flex size-32 items-center justify-center overflow-hidden rounded-3xl bg-ink-foreground/10 p-3 ring-1 ring-ink-foreground/15">
    <StoreLogoImage
      alt={t('login.logoAlt', { name: storeName })}
      className="max-h-full max-w-full object-contain"
    />
  </div>
  {/* Name block */}
  <div className="leading-tight">
    <p className="text-3xl font-semibold tracking-tight">{storeName}</p>
    <p className="mt-1 text-xs text-ink-foreground/60">{t('login.terminal', { id: TERMINAL_ID })}</p>
  </div>
</div>
```

`StoreLogoImage` renders `object-contain` (not `object-cover`, unlike Phase 31's square product-photo
crop) — a logo must never be cropped, and the `p-3` inset plus the light `ink-foreground/10` backdrop keeps
any logo (light or dark, transparent or opaque background) legible against the always-dark `ink` panel.

**Configured but only one of the two is set** (partial state — must not crash or look broken):
- `storeName` set, no `storeLogoPath`: render the name block exactly as above; render the hero tile with the
  **same fallback icon treatment as unconfigured** (`ShoppingBasket`, centered, at the hero 128px size — not
  the small 44px size, since the tile itself is already rendered at hero dimensions in this branch).
- `storeLogoPath` set, no `storeName` (should not normally happen given the schema's `min(1)`, but the UI
  must not break on it): render the hero logo tile as above; render `t('login.brand')` in the name slot.

**Unconfigured** (both empty/unset — today's exact current behavior, D-03, "zero new fallback design"):

```
<div className="relative flex items-center gap-3">
  <div className="flex size-11 items-center justify-center overflow-hidden rounded-xl bg-ink-foreground/10 ring-1 ring-ink-foreground/15">
    <ShoppingBasket className="size-5" aria-hidden="true" />
  </div>
  <div className="leading-tight">
    <p className="text-sm font-semibold tracking-tight">{t('login.brand')}</p>
    <p className="text-xs text-ink-foreground/60">{t('login.terminal', { id: TERMINAL_ID })}</p>
  </div>
</div>
```

This is the **exact existing markup** (unchanged size, unchanged copy) — it is not scaled up, matching D-03's
explicit "zero new fallback design" instruction. Do not merge this into a single "hero-size-always" component;
the two branches render genuinely different tile sizes (128px vs. 44px) by design.

**Loading state:** while `useSettings()`/the signed-logo-URL query is in flight, render the **unconfigured**
branch (not a skeleton) — avoids a size-jump flash from small-fallback → skeleton → hero, and matches the
existing page's current "no loading flicker" behavior (the pre-phase code never showed a loading state for
this block either, since `logoDataUrl` was already in the settings payload). If the signed-URL fetch itself
is slow after `general` has already resolved with a `storeLogoPath` set, show the hero tile with a `Skeleton
className="size-32 rounded-3xl"` in place of `StoreLogoImage` — do not fall back to the small icon once a
`storeName`/`storeLogoPath` are known to exist.

**Error state (image fails to load, e.g. broken signed URL):** hero tile falls back to `ImageOff` centered at
`size-8`, keeping the hero 128px frame and the `storeName` text as-is (the *name* is a simple string and can't
"fail to load" — only the image can). Never falls back to the unconfigured branch's small tile+generic-string
pairing once a real `storeName` is known.

Same interaction surface as Phase 31's Photo tab, scaled down for an inline settings row rather than a
dedicated tab panel: drag-and-drop onto the tile, click/Enter/Space opens the file picker, clipboard paste
while the tile or its buttons have focus. Same validated constraints as Phase 31 (D-08): 10MB pre-resize cap,
JPEG/PNG/WebP only, re-encoded to WebP with a JPEG fallback, 800px max edge (D-07).

| State | Rendering |
|-------|-----------|
| Empty (`storeLogoPath` null) | Dashed `size-20` tile with `ImagePlus size-6 text-muted-foreground`; single `outline` button `logoChooseFile`; hint text below. |
| Drag-over | Tile swaps to `border-brand bg-brand-soft/80` (mirrors Phase 31's drop-zone drag-over, `FileDropZone`-equivalent). |
| Processing (resize/encode) | Tile keeps its size; `LoadingSpinner` centered inside it; buttons disabled; hint text swaps to `logoProcessing`. |
| Uploading | Tile dimmed under `absolute inset-0 bg-popover/70` + `LoadingSpinner`; hint text swaps to `logoUploading`; buttons disabled. |
| Populated | Solid-border `size-20` tile with the logo `object-contain`; button row becomes `outline` `logoReplace` (Upload icon) + `destructive` `logoRemove` (Trash2 icon). |
| Signed-URL loading (populated row, URL not yet resolved) | `Skeleton className="size-20 rounded-xl"` in place of the tile. |
| Signed-URL / image load failed | Tile shows `ImageOff size-5 text-muted-foreground`; Replace/Remove stay enabled so the admin can recover. |
| Validation / upload error | Inline `<p role="alert" class="text-sm text-destructive">` under the button row with the specific message (see copy table below); also `toast.error` with the same string, matching `GeneralSettingsTab`'s existing save-error pattern. Tile returns to its previous state. |
| Offline | Any entry path → inline `logoErrorOffline`; nothing is read from the file (mirrors Phase 31 D-08's online gate). |

**Remove confirmation:** clicking `logoRemove` opens `ConfirmDialog variant="destructive"` with
`logoRemoveConfirmTitle`/`logoRemoveConfirmDescription`, confirm label `logoRemoveConfirmLabel`, cancel label
`logoRemoveConfirmCancelLabel` — same pattern as Phase 31's Remove-photo confirm.

**Save button interaction:** the logo upload/remove commits immediately on its own action (matches Phase 31's
"photo commits at upload time," D-05 of that phase) — it is **not** batched into the existing `storeName`
field's dirty-state/Save-button flow, since the underlying mutation (a Storage upload + a settings-blob
read-merge-write, per RESEARCH.md Pitfall 2) is independent of the text-field form state. The existing
`storeName`/address/etc. fields keep their current "dirty → Save General button enables" behavior unchanged.

### Motion & reduced motion

Only inherited motion: `transition-colors duration-150` on the settings dropzone tile (mirrors Phase 31's
drop zone), and the login page's existing `animate-fade-up` on page content. No new keyframes.
`prefers-reduced-motion` is handled globally in `globals.css`.

### Keyboard & focus

Settings logo tile is a single tab stop (`role="button" tabIndex={0}`, Enter/Space opens the file picker),
consistent with Phase 31's drop zone. Login hero tile is decorative (not interactive — no upload affordance
