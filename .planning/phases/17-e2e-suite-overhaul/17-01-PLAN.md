<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Test harness → Postgres (service-role) | `db-assertions.ts` uses `SUPABASE_SERVICE_ROLE_KEY` via `getServiceClient()`, bypassing RLS entirely — valid for reading ground truth after a UI action, never valid for asserting an RLS *denial* |
| Local filesystem → Playwright config | `findAgentBrowserChrome()` reads `~/.agent-browser/browsers/` at config-load time; a missing directory must degrade gracefully, not crash the whole test run |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

Wave 1's companion plan (17-03) adds a *separate* `rls-clients.ts` module specifically for anon-key signed-in RLS checks, keeping the two concerns unmistakably apart. |
| T-17-02 | Information Disclosure | `e2e/helpers/db-assertions.ts` | high | mitigate | Service-role key is read exclusively through `getServiceClient()` (`process.env.SUPABASE_SERVICE_ROLE_KEY`), never hardcoded or duplicated — verified by the acceptance-criteria grep gate. |
| T-17-03 | Denial of Service (config) | `playwright.config.ts`'s `findAgentBrowserChrome()` | low | accept | A missing/unreadable `~/.agent-browser/browsers` directory is caught and returns `undefined`, falling back to Playwright's bundled Chromium rather than crashing config load. |
