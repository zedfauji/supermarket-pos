<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → Storage signing endpoint | The batch signer is handed object paths read from product rows; a forged path would request a signature for an arbitrary key |
| signed URL → `<img src>` | Every thumbnail URL leaves the app and is replayable for its TTL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31-11 | Information Disclosure | batch signing of arbitrary object paths | medium | mitigate | Paths handed to `createSignedUrls` come only from `Product.photoPath` values already returned by an RLS-filtered `products` read; the signer is never called with a caller-supplied string. The Storage SELECT policy remains the authorization boundary regardless. |
| T-31-12 | Denial of Service | one signing request per row on a large catalog | low | mitigate | List surfaces use the batch call with a de-duplicated path list and a TanStack cache keyed on that list; Task 3 asserts an exact request count of 1 per page. |
| T-31-13 | Elevation of Privilege | row click widening write access | low | mitigate | Row click only opens the same dialog the Edit button already opened; no new write path and no RBAC change. The cashier-denial coverage in `e2e/products/product-management.spec.ts` (Plan 02) still gates the surface. |
| T-31-SC | Tampering | npm/pip/cargo installs | low | accept | No packages are installed by this plan. |
</threat_model>
