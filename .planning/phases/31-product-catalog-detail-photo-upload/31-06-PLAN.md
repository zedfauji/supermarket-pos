<objective>
Close the one blocking gap from 31-VERIFICATION.md (score 6/7, independently confirmed by 31-REVIEW.md
CR-01): `useProductsForManagement()` and the create-mutation's post-insert refetch in
`src/entities/product/model/queries.ts` select products without the
`inventory(quantity_on_hand, low_stock_threshold)` join that the sibling `useProducts()` already has,
so `ProductDetailDialog`'s D-17 stock strip always reads "0 on hand / No threshold" for every existing
product and its low-stock badge can never render. This directly undermines the phase goal's "full
product detail" claim and PCAT-01/PCAT-02. Fix is a two-line select addition per query, proven by a
real seeded-inventory E2E assertion (not just strip visibility, which is all PM9/PM11 already checked
and is why this regression shipped undetected).

Also folds in 31-REVIEW.md's WR-01 warning (real correctness gap, not cosmetic): `ProductDetailDialog`'s
`unitsPerPackage` handler uses `Number.parseInt`, which silently truncates a manually-typed decimal
(`2.5` -> `2`) instead of failing validation, so a manager can save a wrong `unitsPerPackage` with no
error shown — a genuine hole in PCAT-02's "every existing editable field remains editable" (correctly).

31-REVIEW.md's IN-01 (client 10MB vs bucket 2MB upload-limit mismatch) and IN-02 (unmemoized
`photoColumn` causing thumbnail-flicker) are explicitly deferred, not bundled here — both are
info-level/cosmetic per 31-VERIFICATION.md's Anti-Patterns table, neither is in VERIFICATION.md's
`missing:` list, and both are single-purpose changes unrelated to the queries.ts/stock-strip fix this
plan is scoped around. Revisit only if either is observed causing a real user-facing failure.

Purpose: The dialog's stock strip is a named, deliberate D-17 feature of "full product detail" — the
phase goal is not actually met while it is silently wrong for every product with real stock.
Output: Two corrected `queries.ts` selects, one tightened validation guard, and three new/extended
Playwright assertions that fail against the current code and pass after the fix (TDD RED->GREEN, per
this project's tdd_mode).
</objective>
