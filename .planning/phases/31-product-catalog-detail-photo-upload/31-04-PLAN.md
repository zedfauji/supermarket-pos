<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| clipboard / drag payload → upload pipeline | Dropped and pasted bytes are entirely attacker-controllable in both content and declared type |
| renderer → Storage delete | A remove or replace issues a delete for an object path; a forged path would delete someone else's object |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31-14 | Tampering | drop and paste entry paths | high | mitigate | Both converge on the same `validatePhotoFile` and `resizePhoto` pipeline as the picker — there is no second, unvalidated path — and the bucket's server-side MIME allow-list and size limit backstop all three regardless of what the client claims. |
| T-31-15 | Elevation of Privilege | Storage delete on remove and replace | high | mitigate | The delete target is always the path read from the product row, never a caller-supplied string, and the `storage.objects` DELETE policy still requires the `manage_products` predicate; Plan 05 proves the denial. |
| T-31-16 | Denial of Service | repeated drops during an in-flight upload | low | mitigate | The file input and both action buttons are disabled in all three in-flight states, so a second upload cannot start before the first settles. |
| T-31-17 | Information Disclosure | a signed URL for a replaced photo still in a cache | medium | mitigate | Replace writes a new uuid key and deletes the old, so a cached or leaked URL for the previous photo resolves to a deleted object; Task 3 asserts the old path is gone from the bucket. |
| T-31-SC | Tampering | npm/pip/cargo installs | low | accept | No packages are installed by this plan — drag-and-drop, clipboard, and canvas are all native browser APIs. Task 1 acceptance asserts `package.json` and `package-lock.json` are untouched. |
</threat_model>
