# Phase 31 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the reshaped product dialog (`ProductDetailDialog` — Details / Photo / Links
vertical tabs + read-only stock strip + persistent footer), the catalog row-click affordance and optional
thumbnail column in `CatalogProductsTab`, and every new UI string. All 17 CONTEXT.md decisions (D-01..D-17)
are treated as locked and are not re-asked; every unanswered design question below is resolved with a
default derived from the existing "Counter" token system (`src/app/globals.css`, `DESIGN-TOKENS.md`) and
the rationale is recorded inline. This session was non-interactive — no user questions were asked.

| Role | Size | Weight | Line Height | Where |

## Layout & Interaction Contract

**Focal point per surface:** Details tab → the Name input (full-width first row, receives focus on open in both
modes); Photo tab → the 320px drop zone / preview (the only large element, centred); Links tab → the Units-per-package
input (first field); footer → the Save button (ink fill, `focusEmphasis="high"`, right-most). Everything else is
secondary and rendered in `muted` / `outline` treatment.

### Dialog skeleton (one component, create + edit — D-03)

```
DialogContent  max-w-4xl  max-h-[80vh]  flex flex-col overflow-hidden  (p-6 inherited)
├─ DialogHeader                       pr-8 (clears the close button)
│  ├─ DialogTitle                     productsTab.newProductTitle | productsTab.editProductTitle (existing keys — E2E selects the dialog by this accessible name)
│  └─ Stock strip (D-17, edit mode only; hidden on create — there is no data yet)
│       flex flex-wrap items-center gap-x-6 gap-y-2 pt-2
│       [Eyebrow "En existencia" / 14px 600 text-numeric qty  (+ Badge warning "Stock bajo" when threshold != null && qty <= threshold)]
│       [Eyebrow "Umbral de stock bajo" / value or "Sin umbral" muted]
│       [Badge success "Activo" | Badge muted "Inactivo"]
├─ Body   grid min-h-0 flex-1 gap-6 lg:grid-cols-[13rem_minmax(0,1fr)]
│  ├─ VerticalTabsList  aria-label=productDialog.navLabel  self-start
│  │    Trigger details  icon FileText  label tabs.details  description tabs.detailsDescription
│  │    Trigger photo    icon Image     label tabs.photo    description (create: photo.lockedTitle | edit: tabs.photoDescription)  disabled={isCreate}
│  │    Trigger links    icon Link2     label tabs.links    description tabs.linksDescription
│  │    (any trigger with errors: badge = <span class="size-2 rounded-full bg-destructive"/> and label = t('productDialog.tabWithErrors', {label}))
│  └─ Panel wrapper   min-h-0 overflow-y-auto  ← the ONLY scroll region (D-08 / Pitfall 2)
│       TabsContent × 3   rounded-xl border border-border bg-card p-4 lg:p-6 shadow-xs
└─ DialogFooter (inherited bleed styling)  showCloseButton={false}
     [_form error, if any: mr-auto text-sm text-destructive role="alert"]
     POSButton outline  common:actions.cancel
     POSButton default  focusEmphasis="high"  (isCreate ? productForm.createProduct : productForm.saveProduct) | common:actions.saving while pending
```

`<form>` wraps Body + Footer so Enter submits from any tab; the old `max-h-[min(70vh,560px)] overflow-y-auto` on the
form is removed (D-08). Below `lg`: rail becomes a horizontal strip (inherited), field grids collapse to one column.

SKU | Barcode (`data-testid="product-form-barcode"` kept) · Active checkbox (`lg:col-span-2`). Field logic, Zod

### Links tab (D-02)

### Photo tab (D-09..D-12, D-16)

Edit mode only (trigger disabled on create). Content is `flex flex-col items-center gap-4`:

| State | Rendering |
|-------|-----------|
| **Empty (no `photoPath`)** | Drop zone: `aspect-square w-full max-w-[20rem] rounded-xl border-2 border-dashed border-border-strong bg-card transition-colors duration-150`, `role="button" tabIndex=0 aria-label=photo.chooseFile`, Enter/Space opens the hidden `<input type="file" accept="image/jpeg,image/png,image/webp" data-testid="product-photo-file-input">`. Inside: `EmptyState className="[&_h3]:text-lg" icon={ImagePlus} title=photo.emptyTitle description=photo.emptyBody action={photo.chooseFile}` (EmptyState's action Button gets `min-h-[44px]`). Below the zone: `text-sm text-muted-foreground` `photo.formatsHint`. |
| **Drag-over** | Zone swaps to `border-brand bg-brand-soft/80`; an absolutely positioned `pointer-events-none` overlay shows `photo.dropHere` at 14px 600 `text-brand-strong` (mirrors `FileDropZone`). |
| **Paste** | `onPaste` listener on `DialogContent` while the Photo tab is active; first `clipboardData.files` image item enters the same pipeline. No visual affordance beyond the copy in `photo.emptyBody`. |
| **Processing (resize/encode)** | Zone keeps its size; centred `LoadingSpinner` + 14px muted `photo.processing`; file input and buttons disabled. |
| **Uploading** | Preview (if replacing) or zone dimmed under `absolute inset-0 bg-popover/70` overlay with `LoadingSpinner` + `photo.uploading`; buttons disabled. Indeterminate (Storage upload has no progress events). |
| **Populated** | `<img data-testid="product-photo-preview" alt=photo.altText(name) class="size-full object-contain p-4">` inside `aspect-square w-full max-w-[20rem] overflow-hidden rounded-xl border border-border bg-muted`. Button row `flex flex-wrap justify-center gap-4`: `POSButton outline` `Upload` icon + `photo.replace` (`data-testid="product-photo-replace"`, opens picker; drop/paste also replace) · `POSButton destructive` `Trash2` icon + `photo.remove` (`data-testid="product-photo-remove"`, opens `ConfirmDialog`). |
| **Signed-URL loading** | `Skeleton` in the preview frame (same 320px square, `rounded-xl`). |
| **Signed-URL / image load failed** | Preview frame shows `ImageOff` size-10 muted + 14px `photo.errorLoad`; Replace/Remove stay enabled so the operator can recover. |
| **Validation / upload error** | Inline `<p role="alert" class="text-sm text-destructive text-center max-w-[20rem]">` directly under the zone/preview with the specific message (see copy table); zone returns to its previous state. Also `toast.error` with the same string for parity with existing save errors. |
| **Offline** | On any entry path, `isOnline()` false → inline error `photo.errorOffline`; nothing is read from the file. |

Photo commits at upload time (D-05): after a successful upload+link, `toast.success(photo.uploaded)`, the preview
swaps to the new object, and the catalog query is invalidated so the thumbnail updates. Remove: after confirm,
`toast.success(photo.removed)` and the tab returns to Empty.

### Create-then-stay (D-03)

After a successful create: `toast.success(productsTab.productCreated)`, the dialog **stays open**, the title flips
to `editProductTitle`, the stock strip appears (qty 0 / threshold "Sin umbral" / Activo), the Photo trigger enables
and its description flips to `tabs.photoDescription`. Focus stays on the Save button. Cancel/close now behaves as
edit-mode close.

### Error navigation (D-06)

On submit with `fieldErrors`: map keys → tabs (`name|categoryId|basePrice|sku|barcode|isActive` → details;
`unitsPerPackage|parentProductId|modifiers|imageUrl` → links). If the first erroring tab ≠ active tab, set the
controlled `value` to it, then move focus to the first `[aria-invalid="true"]` control in that panel. Every tab with
≥1 error shows the destructive dot + `tabWithErrors` label until the next submit clears `fieldErrors`.

### Dirty close (D-07)

Dirty = any field state ≠ its initial value (photo changes are already committed and never count). On `onOpenChange(false)`
(X, Esc, outside click) or Cancel while dirty → `ConfirmDialog variant="destructive"` with `discardTitle` /
`discardDescription`, confirm `discardConfirmLabel`, cancel `keepEditing`. Not dirty → close immediately. Tab
switching never prompts.

### Catalog table (D-04 + discretion: thumbnail = yes)

- New first column `photoHeader` (`w-14`): `<img class="size-10 rounded-md object-cover bg-muted" alt="">` from the
  **batch** signer (D-16, one `createSignedUrls` call per page of rows); `Skeleton size-10 rounded-md` while resolving;
  no photo → `div size-10 rounded-md bg-muted flex items-center justify-center` with `ImageOff size-4 text-muted-foreground`
  and `sr-only` `productsTab.noPhoto`. Thumbnail alt is empty because the Name cell carries the name.
- Rows: `cursor-pointer hover:bg-muted/50 transition-colors duration-150`; `onRowClick` opens the dialog. Keyboard
  path remains the existing Edit button (rows are not made focusable — no new ARIA role on `<tr>`).
- Inline Name/Category/Price cells and the Edit/Deactivate buttons all `stopPropagation` on click (Pitfall 1).
- `productsTab.headerHelp` copy updated to mention row click (see copy table). Existing Edit/Deactivate labels unchanged.

### Motion & reduced motion

Only inherited motion: `TabsContent` `animate-fade-in`, dialog `zoom-in-95` entrance, `transition-colors
duration-150` on the drop zone and row hover. No new keyframes. `prefers-reduced-motion` is handled globally in
`globals.css`.

### Keyboard & focus summary

Tab order: title close button → rail triggers (arrow keys move between tabs, Radix) → active panel fields → footer
Cancel → Save. Drop zone is a single tab stop. Focus-visible ring is the inherited `ring-ring` (brand). Save carries
`focusEmphasis="high"`.

Destructive actions in this phase: **Remove photo** (ConfirmDialog, destructive; confirm `removeConfirmLabel`, cancel
`removeConfirmCancelLabel`) · **Discard unsaved changes** (ConfirmDialog, destructive; confirm `discardConfirmLabel`,
cancel `keepEditing`) · **Deactivate product** (existing row action, unchanged). Confirm labels always repeat the
action + object ("Quitar foto", "Descartar cambios") — never a bare verb. None fire without confirmation.

Error copy rule (D-11): every rejection names the offending thing (type, size) and the next step; the generic
`{{message}}` from `Result.error.message` is appended only for server/network failures.
