<objective>
Thread the new required `settings: ReceiptSettings` parameter (Plan 01's `buildThermalReceiptText` signature) and the new `logoDataUrl`/`paperWidthChars` Tauri-command arguments (Plan 02's `print_receipt` signature) through every real production call site: `pos-printer.ts`, `email-receipt.ts`, `ReceiptPreview.tsx`, `EmailReceiptDialog.tsx`, `PaymentForm.tsx`. This is RESEARCH.md's Summary's "load-bearing work for RCPD-01" made real — a saved setting only matters once every consumer actually reads it.

Per RESEARCH.md Pattern 1: `pos-printer.ts`/`email-receipt.ts` are plain `shared/lib` functions with no hook access, so their callers must pass `settings` in explicitly — never reach into the TanStack Query cache from `shared/lib` (that would invert the FSD import direction).

Purpose: Make the settings wiring from Plan 01/02 reach every real print/preview/email path.
Output: No production code path builds/prints/emails a receipt without real ReceiptSettings.
</objective>
