<objective>
Phase 12 adds a non-blocking `sonner` confirm toast that gates add-to-cart, via the barcode-scan path, for exactly two conditions on an already-resolved active product: `basePrice === 0` ("zero-price") and `quantityOnHand <= lowStockThreshold` ("low-stock", D-02). A clean match still adds in one action with no added step — the fast-checkout core value is unaffected.

**Assumption-delta note:** `gsd_run query assumption-delta scan "12"` flagged ROADMAP.md's literal "multiple products for one barcode" wording (pluralization signal). Decision: **no-change**. CONTEXT.md D-01 already resolved this before this planning pass — `products.barcode` carries a DB-unique partial index, so "multiple products per barcode" is provably impossible in this schema; VER-01's real implementation scope is the two flag conditions above, not a multi-match resolution UI. No identity-model change is needed; this note exists only to close the detector's loop.

This plan (12-01) builds the shared mechanism — the pure risk predicate, the shared confirm-toast hook, and the data plumbing (`inventory` join) both live in `entities/product/model/` per the FSD boundary constraint (`features` cannot import `features`; both `features` and `widgets` may import `entities`) — and wires it into the barcode-scan path only. Plan 12-02 (depends on this plan) reuses the same predicate/hook for the manual-search path and adds the `ProductCard` barcode line (VER-02).

Task 1 is the tracer: the thinnest real end-to-end slice (zero-price scan → confirm → add) that needs no new DB join at all, since `basePrice` is already on every `Product`. Task 2 expands to low-stock, which does need the new `inventory` embed to make `quantityOnHand`/`lowStockThreshold` reachable.

Purpose: catch add-to-cart mistakes (free/mispriced items, stock about to go negative) without slowing down the happy path for every other scan.
Output: `getProductRiskFlag()` (TDD, Vitest-covered), `useConfirmRiskyAdd()`, `useScanBarcodeToCart` wired to both, new `entities:productRiskConfirm.*` i18n keys, extended `e2e/51-barcode-scan-search.spec.ts`.
</objective>
