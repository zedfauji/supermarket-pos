## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (any authenticated session) -> `brands` table | Write ops (INSERT/UPDATE/DELETE) are attacker-controllable through devtools regardless of client-side RBAC UI gating |
| Client -> `products.brand_id`/`weight_amount`/`weight_unit` | New columns on an already RLS-gated table; the write boundary is row-level, not column-level |
| Pre-auth/anon render path -> `brands` SELECT | The POS grid's filter dropdown (Plan 02) must read brand names before/without necessarily being mid-authenticated-session in every render path |
