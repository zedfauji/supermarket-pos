> Visual and interaction contract for Checkout continuity, guarded Settings exits, and cash
> tender entry. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

## Design System

| Property          | Value                                                                                          |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| Tool              | Existing shadcn configuration; reuse repository primitives only                                |
| Preset            | `radix-nova`, neutral base, subtle menu accent                                                 |

### Reuse Contract

| Need                            | Existing primitive/pattern                      | Contract                                                                                              |
| ------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Blocking decisions              | `@shared/ui/alert-dialog`                       | Reuse its overlay, focus trap, 24px padding, 16px radius, and 56px actions.                           |
| Status and failure messaging    | `@shared/ui/alert`                              | Use `warning`, `destructive`, `success`, or `info`; never encode state by color alone.                |
| Saved basket and receipt values | `ScrollArea`, `MoneyDisplay`, `Badge`           | Keep currency tabular and show full item identity and quantity.                                       |
| Tender entry                    | `MoneyInput`, `POSButton`, `@shared/ui/popover` | One controlled composite; screen and hardware input share one amount buffer.                          |
| Key layout                      | `PINKeypad`, `WeightEntryDialog`                | Reuse the three-column, large-target visual rhythm, not their global key handlers.                    |
| Settings exit                   | Existing Settings tabs plus `AlertDialog`       | One application-level dialog; individual forms continue to own values, validation, Save, and Discard. |

Do not add a second design system, a second modal primitive, or a new keypad dependency.

  `max-height: calc(100dvh - 32px)`.

  surface after reconciliation.
- Settings exit dialog: existing `max-width: 512px`, 24px padding, and 8px action gaps.
- Cash keypad popover: 12px outer padding, 8px key gaps, 56px minimum key height, 320px maximum
  width, and 4px anchor offset.

## Interaction Contract

### 1. Saved Sale Handoff

1. After authentication and current-caja validation, a valid saved sale with Checkout open displays
   a modal `AlertDialog` before Checkout content is mounted or revealed.
2. The header shows the title and current caja/session context without naming the previous cashier.
   The body contains the full saved basket, saved total, payment method, tendered amount, split
   allocations, promotion/custom discount, and applicable customer/reference fields. Omit empty
   optional rows; never render secret fields.
3. Each basket row shows full product name, quantity or weight, saved unit price, and saved line
   total. The footer repeats the saved sale total. A long basket scrolls inside the body while the
   title and actions remain visible.
4. **Resume Sale** is the single brand action and receives initial focus. **Discard Sale** is
   destructive. Escape and outside click do nothing because the decision is mandatory; no close
   control is rendered.
5. Resume opens Checkout with the saved draft. Discard clears the active sale and draft, returns to
   the ordinary empty Checkout, and restores focus to product search.
6. A saved cart whose Checkout-open marker is absent restores directly to the selling screen without
   this dialog. A malformed, obsolete, partial, caja-mismatched, or empty envelope fails closed to
   the existing empty-cart state and never flashes persisted content.

### 2. Restored-Value Review

- After Resume, compare the saved snapshot with current product, price/promotion, and stock data.
  Checkout remains visible, but Pay and cart mutation controls stay disabled until comparison ends.
- If nothing changed, show a compact success/info notice, announce “Restored sale ready,” and enable
  normal editing and payment.
- Changed rows receive a warning border and a **Needs review** badge. A review panel presents Saved
  and Current values side by side, then **Accept Current Values** and **Remove Item**. Acceptance
  applies the current price/promotion/stock decision explicitly and clears that row's warning.
- If the product or inventory record is unavailable, show Current as **Unavailable** and offer only
  **Remove Item**. Never offer acceptance without an authoritative current value.
- Keep the existing Pay action disabled while any conflict remains. State and copy—not a manager
  bypass—explain why.

### 3. Submitted Payment Recovery

| State             | Visual contract                                                                                                                                                                   | Available actions                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Reconciling       | Blocking centered status surface with spinner, saved basket summary, total, and `aria-live="polite"` copy. Cart and payment UI are inert and visually dimmed beneath the overlay. | App close only; no Escape, outside dismissal, edit, Pay, or Discard.                   |
| Completed         | Transition directly to the existing receipt view with a brief “Payment confirmed” live announcement.                                                                              | Existing Print, Email, PDF, and Done actions; never trigger Print automatically.       |
| Incomplete        | Restore Checkout fields exactly and show an info banner that the original payment reference will be reused.                                                                       | Normal review plus the existing explicit Pay action; no automatic retry.               |
| Unknown / offline | Replace the spinner with warning icon, actionable copy, and persistent saved summary.                                                                                             | **Retry Status Check** and app close only; no Pay, edit, Discard, or manager override. |

Retry keeps the same dialog and stable layout; it swaps the warning block for the spinner so focus
does not jump. Disable Retry and label it **Checking…** during the request. Backend details never
appear in the message.

### 4. Settings Exit Guard

1. Intercept dirty Settings tab changes, route navigation, sign-out, and Tauri close before any
   navigation/sign-out/close side effect occurs. Browser reload/window close uses only the native
   browser warning.
2. Show one `AlertDialog` titled **Unsaved changes** with exactly three actions:
   **Save and Continue** (brand), **Discard Changes** (destructive), and **Stay Here** (outline).
   Initial focus is **Stay Here**, the safest action.
3. Escape, outside click, and the 44px top-right close control all invoke **Stay Here**: cancel the
   pending exit, preserve values, and return focus to the control that attempted the exit.
4. Save changes its label to **Saving…**, adds a spinner, and disables all three actions until the
   owning mutation settles. Success closes the dialog and continues the original exit exactly once.
5. Failed validation or mutation leaves the dialog open, preserves every field, renders the
   destructive alert above the footer, focuses the first invalid field for validation failures or
   the alert for mutation failures, and changes Save to **Retry Save**.
6. Discard resets the mounted form, clears event-dirty state, and continues the original exit once.
   Stay cancels it. Repeated navigation/close attempts never replace the first pending target.
7. A form remains dirty after any edit until explicit Save or Discard, even when the current value
   equals its original value. Backup remains read-only/action-only and does not register a draft.

### 5. Cash Tender Keypad

- Use one controlled, non-modal `Popover` anchored to each cash **Amount tendered** input: the main
  cash field and each split-cash tendered field. Do not attach it to split allocation, discount,
  card, transfer, or reference fields.
- Focusing or activating the cash field opens the popover. Pointer use inside the popover keeps the
  input composite active. Escape or focus leaving the entire composite closes it and returns focus
  to the amount field when Escape initiated the close.
- Key order is the familiar three-column layout: `7 8 9`, `4 5 6`, `1 2 3`, then `Clear 0 .`, with
  Backspace spanning all three columns. Every key is at least 56px high. Clear and Backspace include
  text/accessibility labels; the backspace icon is decorative.
- Digits append as normal decimal text: `1`, `0`, `0` displays `100.00`; the decimal key starts or
  continues cents, permits only one decimal separator, and limits the fractional part to two digits.
  Empty/Clear normalizes to `0.00` without an error.
- Existing Exact and quick-tender controls remain directly below the field. Selecting one arms
  replacement: the next keypad or physical digit replaces the preset, then later digits append.
  Decimal, Backspace, or Clear edit the selected preset rather than submitting it.
- While the keypad is open and its amount input owns focus, top-row/numpad digits, decimal,
  Backspace, and Delete dispatch the same intents as pointer keys. Delete means Clear. Prevent Enter
  from submitting or activating Pay. Do not install a page-global keypad handler.
- During payment processing, the input, popover keys, Exact, and quick-tender actions are all
  disabled. An already-open popover remains visible but inert, preventing layout/focus jumps.
- The current amount is announced politely after pointer input but not duplicated for native input
  typing. The visual input remains the single accessible value field.

## Responsive and Motion Contract

- At 1024px and wider, keep the existing two-column PaymentForm. Position the keypad below and
  start-aligned to the tender input; Radix collision handling may flip it upward, but it must not
  cover the Pay action or saved-order summary.
- Below 640px, dialogs use a 16px viewport gutter, stack actions to full width, and constrain basket
  content to the remaining vertical space. The keypad stays a popover, never a separate modal or
  permanently visible panel, with width `min(320px, calc(100vw - 32px))`.
- Basket rows change from side-by-side saved/current columns to stacked labeled values below 480px.
  Action labels wrap to two lines without reducing target height.
- Reuse existing 150–250ms fade/scale transitions. State changes must remain understandable with
  `prefers-reduced-motion`; reduced motion removes translation/scale and retains opacity only.
- Do not animate totals, progress through recovery states, or the dismissal of destructive errors.

## Accessibility Contract

- Every custom dialog has a programmatic title and description. Mandatory recovery dialogs trap
  focus and cannot be dismissed to an unsafe state.
- On dialog close, return focus to the initiating Settings tab/link/control; after saved-sale
  Discard, focus product search; after Resume, focus the first actionable Checkout control.
- Reconciliation changes use `role="status"`/`aria-live="polite"`; save/recovery failures use
  `role="alert"`. Do not announce the continuously formatted amount twice.
- Icon-only controls have translated accessible names and at least 44px targets. All keypad buttons
  use `type="button"` and remain reachable in row-major Tab order.
- Warning, success, and destructive states combine semantic copy, icons, and existing tokens; color
  never carries meaning alone.
- Automated keyboard coverage must include Tab order, Escape behavior, Enter suppression, top-row
  and numpad digits, decimal, Backspace, Delete, Clear, quick-tender replacement, focus return, and
  disabled processing state in both locales.
