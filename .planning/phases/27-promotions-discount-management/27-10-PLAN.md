<objective>
Fix Part A of gap G-27-8 (quick, isolated bug — ships independently of the larger wizard redesign in
plans 27-11..27-15): the promotion discount-percent field is stuck at 0 because `discountValue` is
NUMBER-typed React state (`useState(0)`) coerced via `Number(e.target.value)` on every keystroke, with
no string buffer. Clearing the field yields `Number('') === 0`, which the controlled `value` prop
redisplays as the literal digit `'0'`; new digits then insert BEFORE that persistent `'0'` instead of
replacing it (`'02'`, `'020'`, ...). Root cause fully diagnosed in
`.planning/debug/promotion-dialog-ux-and-scope-gaps.md` (Part A), confirmed live in a real browser via
a temporary Playwright repro.

`NearExpirySettingsTab.tsx`'s sibling percent field (STRING state, `Number()` coercion deferred to
save time only) does not have this defect — that is the pattern to copy verbatim.

Purpose: this bug currently makes it impossible to create a percent-type promotion through the app UI
at all (the field cannot be set to a nonzero value), independent of the larger scope/wizard redesign
tracked separately. Ships fast so admins can create percent promotions immediately.

Note: this file will later be deleted/replaced entirely by the new wizard screen (plan 27-14) — this
fix is still worth shipping now for interim value, and the wizard's own percent field will reuse this
same corrected string-buffered pattern (not reintroduce the bug).

Output: A working percent-discount input field, proven by both a unit test and a permanent Playwright
E2E test (per this project's mandatory-automated-testing policy — no manual UAT).
</objective>
