<objective>
Build the actual user-facing redesign the UAT report asked for: replace `PromotionFormDialog.tsx`'s
cramped, single-step, non-paginated modal with a dedicated multi-step wizard screen. This is the
capstone of Part B (gap G-27-8) — everything plans 27-11..27-13 built (schema, atomic RPC, entity
hooks, MultiSelectCombobox, CategoryTreePicker multi-select, DateRangePicker forward-looking presets)
exists specifically so this plan can compose it into the screen the UAT report described: "it shouldn't
be any dialogue... a search options and multi select should be there... A promotion could be blank
also... Time based Promotions should be also there... It shouldn't be on the same screen, it could be
multiple screens and flow. A Wizard will do it... on exit it should validate if everything's alright."

Purpose: close the UI/UX half of gap G-27-8 (Part B) — the schema/data half is already proven by
27-11's integration tests and 27-12's pricing-engine tests.
Output: `/promotions/new` and `/promotions/:id/edit` routes, a 3-step wizard widget, and retirement of
the old dialog.
</objective>
