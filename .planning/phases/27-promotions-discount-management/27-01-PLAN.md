<objective>
Build the full backend spine for promotions: a new `promotions` table with RLS, the
`process_direct_sale_atomic` extension that makes the RPC the sole, server-side, best-price-wins
promotion authority (product/category scope + expiry-proximity trigger), the below-cost floor guard
with manager-override, re-enabling the existing (currently hard-blocked) ad-hoc whole-sale discount
path, and the `order_items` per-line snapshot columns. Also stands up the `entities/promotion`
TypeScript model layer (Zod schema, CRUD query hooks, and the pure `evaluateBestPromotion()` pricing
function client code will reuse in Plan 02/03/04).

Purpose: every later plan (admin UI, live cart display, payment screen, snapshot verification,
offline conflict, E2E matrix) depends on this schema, RPC contract, and entity layer already
existing and proven correct — this is the phase's tracer: one thin, real, end-to-end path (create a
promotion -> a direct sale recomputes and snapshots its discount -> a below-cost combination is
blocked without override) verified against a live database, not mocked.
Output: `promotions` table + RLS + role_permissions rows + `order_items` snapshot columns + audit
trigger; `process_direct_sale_atomic` (18-param signature) computing promotions server-side;
`entities/promotion` model layer; a real RPC integration test proving the whole path.
</objective>
