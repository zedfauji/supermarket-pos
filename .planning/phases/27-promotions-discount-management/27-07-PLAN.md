  <action>
Create e2e/promotions/scope-overlap-resolution.spec.ts: seed a product-scoped promotion (smaller
discount) and a category-scoped promotion (larger discount) both matching one product, both active;
checkout that product and assert the larger (category-scoped) discount applied; then reverse which
one is larger and repeat, proving the winner is discount-amount-driven, not scope-type-driven (D-05
— no scope-specificity override). Also cover the zero-active-promotions baseline: with no promotions
seeded, assert an existing pre-Phase-27 checkout spec's expected list-price totals are unaffected
(cross-reference by running the existing e2e/checkout/happy-path spec name/assertions, not by
duplicating it). Create e2e/promotions/timezone-boundary.spec.ts: read the store's configured
`settings.general.timezone`, seed a promotion whose `ends_at` is "23:59:59 today, store-local time"
(computed from that timezone, not `new Date()`'s host-UTC time), and assert checkout at a moment
that is store-local-today-but-already-UTC-tomorrow still applies the discount (and a moment clearly
past store-local midnight does not). Create e2e/promotions/promotion-deleted-mid-cart.spec.ts: add a
promoted product to the cart, delete the promotion via the admin /promotions UI while the item still
sits in the cart, then attempt checkout — assert the server's authoritative recompute (Plan 01)
either drops the discount cleanly (PRICE_MISMATCH-style client-side retry showing the corrected
total) or, if Plan 06's conflict-flag path already covers this exact scenario for the offline case,
assert the equivalent ONLINE behavior here (a live promotion-deleted-while-in-cart case, distinct
from Plan 06's offline-specific one) — the sale must never silently complete at the stale
discounted price. Ensure fixture teardown (deleted promotion, created promotion, staff/shift/caja
rows) leaves the database in a state where re-running this spec produces identical results, matching
this repo's existing E2E teardown conventions (check `global-teardown.ts` / existing
`afterEach`/`afterAll` patterns in a sibling spec). Create
e2e/promotions/loose-weight-open-unit-interaction.spec.ts: seed a promotion scoped to a loose-weight
product, add a specific weight (e.g. 500g) to the cart, and assert the discount is computed against
that weight-adjusted expected price (price-per-kg * 0.5), not the full per-kg list price; separately
seed a promotion scoped to an open-unit child (loose) product created via the existing
open-open-unit feature, and assert its discount is independent of whatever promotion (if any)
targets its parent box product.
