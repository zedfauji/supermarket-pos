## Design System

| Property | Value |
|----------|-------|

`components.json`'s own `aliases` (`@app/components/ui` etc.) are **not** where this repo's shadcn-style primitives actually live — this is an FSD codebase, and every primitive was hand-placed under `src/shared/ui/` instead. `npx shadcn info` therefore reports "No components installed" even though 25 shadcn-derived primitives exist; do not trust that command's component count for this repo, and do not run `npx shadcn add` targeting the `components.json` alias paths — it would create a second, disconnected `src/app/components/ui/` tree. New primitives this phase needs (see Component Inventory) should be hand-authored into `src/shared/ui/` following the exact pattern of `command.tsx`/`tabs.tsx`, matching this repo's established convention, not pulled via the CLI.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from the rest of the app, confirmed against `PromotionFormDialog.tsx`'s/`FormField.tsx`'s existing `space-y-2`/`space-y-4`/`gap-2` usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip internal padding, icon-to-label gaps |
| sm | 8px | `gap-2`/`space-y-2` — label-to-input, chip-to-chip, day-of-week checkbox row |
| md | 16px | `space-y-4` — field-to-field spacing within a step (existing dialog's default) |
| lg | 24px | Step-container padding, gap between step content and Next/Back nav bar |
| xl | 32px | Gap between the step indicator (Tabs list) and the step content below it |
| 2xl | 48px | Not used in this phase's UI |
| 3xl | 64px | Not used in this phase's UI |

Exceptions: touch targets follow the existing `POSButton` scale (44/56/72px), not the 4px grid directly — this is the established project-wide convention (see `CLAUDE.md` "Touch-target & focus-visible sweep"), not a phase-specific deviation.

## Color

Unchanged theme tokens (oklch CSS variables, `src/app/globals.css`) — this phase adds no new palette, only reuses the existing 60/30/10 split already established app-wide.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--card)` | Wizard page background, step-content card surface |
| Secondary (30%) | `var(--secondary)` / `var(--muted)` | Step indicator (inactive/disabled step tabs), selected-target chip background, day-of-week unchecked checkbox surface |
| Accent (10%) | `var(--primary)` | Active/current step tab, primary CTA (Next / Save Promotion / Create Promotion), checked day-of-week checkboxes, selected-target chip's active state |

Accent (`var(--primary)`) reserved for: the current step's `TabsTrigger`, the Next/Back/Save primary `POSButton`s, checked `Checkbox` fill (day-of-week), and the Review step's live-price-preview "New price" figure (drawing the eye to the computed discount, matching `MoneyDisplay`'s existing emphasis convention). Not used for step icons, borders, or any decorative element.

`pos-warning` (`var(--pos-warning)`, amber) is additionally reserved, project-wide-precedent color, for exactly one new use in this phase: the `needs_review` badge (D-12) on migrated promotions in the list page — same amber already used for `tab_open_warn`/near-expiry alerts, not a new semantic color.

## UI Structure (phase-specific — supplements the standard template)

### Wizard page layout (D-07)

Dedicated route (`/promotions/new`, `/promotions/:id/edit`, per RESEARCH.md Assumption A2), not a modal:

```
PageContainer
└─ SectionHeader (title: "New Promotion" / "Edit Promotion", back-link to /promotions)
└─ Tabs (value=currentStep, onValueChange=gated per D-08/D-10)
   ├─ TabsList (4 triggers, step indicator)
   │  1. Basics & Discount
   │  2. Scope
   │  3. Validity & Recurrence
   │  4. Review
   └─ TabsContent × 4 (one per step, see below)
└─ Nav bar (Back | Next, or Back | Create Promotion/Save Changes on step 4)
```

Step indicator states: **current** (accent `var(--primary)` background/text), **completed & revisitable** (default/outline, clickable), **not-yet-reached in create mode** (`disabled`, muted `var(--muted-foreground)`, per D-08 forward-gating), **all steps enabled in edit mode** (D-10, no `disabled` state ever applied when `promotion != null`).

### Step 1 — Basics & Discount
Reuses `PromotionFormDialog.tsx`'s existing name field + two-button discount-type toggle + percent/amount `FormField` (unchanged fields, unchanged copy) — just relocated into `TabsContent value="basics"`.

### Step 2 — Scope
New `MultiSelectPicker` (Popover + Command, checkboxes per result row, grouped "Products" / "Categories" via `CommandGroup`, category rows indented by `parentId` depth reusing `CategoryTreePicker`'s existing hierarchy logic) + a "Store-wide (no restriction)" `Checkbox` above it that, when checked, disables the picker and clears any selection. Selected items render as removable `Badge` chips below the picker trigger.

### Step 3 — Validity & Recurrence
`DateRangePicker` extended with a `presets` prop — this phase passes forward-looking presets (e.g. "Today onward", "Next 7 Days", "Next 30 Days", "This Month") instead of Reports' backward-looking ones (Today/Yesterday/Last 7 Days/This Month unchanged for Reports' own usage). Below the date range: a "Recurring" toggle (`Switch`, already in inventory) that reveals, when on: 7 day-of-week `Checkbox`es in a single row (Sun–Sat, D-04) and two native `<input type="time">` fields (start/end, D-05) in a `FormField` pair, with the D-05 same-day validation error shown inline.

### Step 4 — Review
Read-only summary of all prior-step values (name, discount, scope chips, date range, recurrence if set) + the D-09 live computed-price preview card (calls `evaluateBestPromotion` client-side against the first matching sample product) + the final `POSButton touchSize="xl"` Create/Save action.
