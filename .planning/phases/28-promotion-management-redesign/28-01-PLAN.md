<objective>
Replace the Phase 27 single-target promotions schema (`product_id`/`category_id` XOR columns) with a
`promotion_targets` junction table supporting multi-product + multi-category + store-wide scope
(D-01/D-02), add day-of-week/time-of-day recurrence columns (D-03..D-06), backfill every pre-existing
row with `needs_review=true` (D-11/D-12), extend `process_direct_sale_atomic`'s candidate-pool matching
for both dimensions, and replace `PromotionFormDialog` with the entry point for the new wizard — a
minimal-but-real single-step version wired end-to-end (name+discount+save), proving the whole stack
before Waves 2 builds out the remaining three wizard steps.

Purpose: This is the phase's tracer — the schema-breaking migration and pricing-engine rewrite that
every later plan in this phase depends on. Landing it first, proven end-to-end via a real checkout,
catches an architectural mistake in the junction-table shape or the recurrence-matching approach before
three more plans build UI on top of it.
Output: New `promotion_targets` table + recurrence columns, extended `process_direct_sale_atomic`,
rewritten `evaluateBestPromotion` pricing engine, a minimal working `/promotions/new` +
`/promotions/:id/edit` wizard route (Basics+Discount step only — Scope/Validity/Review steps expand in
28-03/28-04), `needs_review` surfaced on the list page, and three new/extended E2E specs.
</objective>
